# 작곡과 편곡

## 작업 순서
- 큰 결정에서 작은 결정 순서로 진행
    + 장르, 템포, 조
    + 곡 구성 (섹션 목록과 마디 수, 섹션별 에너지)
    + 코드 진행
    + 리듬 (드럼, 베이스)
    + 주선율과 훅
    + 보조 성부 (아르페지오, 패드, 대선율)
    + 전환 (필인, 라이저, 필터 움직임)
- 단계마다 `lint`로 확인한 뒤 다음 단계로 진행
    + 화성 오류를 늦게 발견할수록 고칠 범위가 커짐

## 곡 길이
- 4/4 박자 한 마디의 길이는 `240 / bpm`초
    + 128 bpm : 1.875초, 3분 30초는 112마디
    + 138 bpm : 1.74초, 7분은 242마디
    + 174 bpm : 1.38초, 4분은 174마디
- 섹션은 4, 8, 16, 32마디 단위가 기본
- 장르별 표준 구성은 `genres <id>`의 Arrangement 항목 참조

## 코드 진행
- 한 곡에 진행은 2-3개면 충분
    + 벌스용, 코러스용, 브리지용
    + 전자음악은 같은 진행을 유지한 채 음색과 밀도로 전개하는 경우가 많음
- 단조 장르의 기본 진행
    + `i | VI | III | VII` : 가장 범용적
    + `VI | VII | i | i` : 상승감, 코러스와 클라이맥스
    + `i | iv | VI | V` : 긴장감 (V는 화성단음계의 장3화음)
    + `i | i | bVII | bVII` : 한 코드 장르의 작은 움직임
- 코러스는 벌스와 다른 코드로 시작하면 구분이 분명해짐
- 로마 숫자로 작성하면 조를 바꿔도 진행이 유지됨

## 선율
- 강박(첫 박, 셋째 박)의 음은 코드 구성음 위주로 배치
    + 경과음과 이웃음은 약박에 배치
- 코드음 바로 위 반음을 길게 끌지 않음
    + 단3화음에서 장3도, 장화음에서 4도가 대표적
- 순차 진행을 기본으로 하고 도약은 한 프레이즈에 한두 번
    + 도약 뒤에는 반대 방향 순차 진행으로 받음
- 프레이즈 끝은 코드의 근음, 3음, 5음 중 하나
    + 근음은 종결감, 5음은 이어지는 느낌
- 훅은 2마디 안팎의 동기를 반복하고 끝만 바꿈
    + 같은 동기를 다른 코드 위에 옮겨 놓는 것이 가장 쉬운 발전 방법
- 코러스 선율은 벌스보다 3도에서 5도 높은 음역에 배치

## 베이스
- 코드가 바뀌는 자리에서는 근음 (슬래시 코드는 베이스음)
- 킥과 같은 자리의 베이스 음은 짧게 또는 비움
    + 포온더플로어 장르의 뒷박 베이스와 롤링 베이스(`. 1 1 1`)가 이 원리
- 음역은 E1에서 C3 사이가 기본
    + 그보다 낮으면 대부분의 재생 장치에서 들리지 않음

## 음역 배치
| 역할 | 권장 중심 음역 | lint 허용 범위 |
|---|---|---|
| sub | E1 - E2 | C1 - D3 |
| bass | E1 - C3 | D1 - C4 |
| pad | C3 - C5 | E2 - E6 |
| chord | C3 - C5 | G2 - E6 |
| keys | C2 - C6 | A1 - D7 |
| arp, pluck | C3 - C6 | C3 - D7 |
| lead | C4 - C6 | E3 - D7 |
| vocal | 목소리의 말하는 음높이에서 위로 한 옥타브 이내 | 엔진별 확인 |
- C3 아래에서는 5도보다 좁은 음정을 겹치지 않음
- 한 옥타브 폭(G3-C5)에 선율 성부가 셋 이상 몰리면 서로 가림
    + 옥타브를 나누거나 하나를 뺌

## 편곡의 에너지 설계
- 섹션마다 `energy`(0-1)를 먼저 정함
    + intro 0.3, verse 0.5, build 0.7, chorus 0.9, drop 1.0, break 0.35가 출발점
- 에너지를 올리는 수단
    + 트랙 수 추가 (특히 하이햇, 라이드, 클랩)
    + 필터 열기 (`auto`의 `lpf`)
    + 음역 확장 (옥타브 위 성부 추가)
    + 리듬 세분화 (8분 하이햇에서 16분 하이햇)
- 에너지를 내리는 수단
    + 킥과 베이스 제거가 가장 큰 효과
    + 필터 닫기, 리버브 많은 패드만 남기기
- 전환 장치
    + 섹션 끝 : `rise`의 riser, snare_roll, reverse_crash
    + 섹션 시작 : `hit`의 crash, impact
    + 드롭 직전 한 마디 또는 한 박 동안 킥을 비움 (`gap`)
    + 브레이크 시작 : downlifter
- 같은 섹션이 다시 나올 때는 한 가지를 바꿈
    + 성부 추가, 화음 추가, 필인 변경, 옥타브 이동 중 하나
- QA가 섹션별 실제 음량 순위와 `energy` 순위를 비교하므로 기획과 결과의 차이를 확인 가능

## 곡의 끝
- 끝 처리는 편곡의 일부
    + 마지막 마디까지 가득 연주하고 멈추면 음악이 잘린 것처럼 들림
- 세 가지 방법 중 하나를 선택
    + 끝맺음 타격 : `ending: hit`, 으뜸화음 한 번과 감쇠 (클럽 장르, 팝)
    + 페이드아웃 : `ending: fade`, 반복형 아웃트로 (로파이, 두머, 신스웨이브 등)
    + 직접 작성 : 성부를 줄여 가는 아웃트로와 마지막 화음
- 아웃트로에서 필터를 닫거나 음량을 내린 경우에도 마지막 지점을 정함
    + 닫힌 채로 끝나는 잔향은 유지되므로 마지막 타격 또는 페이드와 함께 사용

## 그루브
- `swing` : 16분 뒷자리를 늦춤, 하우스 0.04-0.1, 힙합 0.15-0.3
- `humanize: {timing_ms: 5}` : 기계적 정확함이 장르 특성이면 0으로 둠
- 세기 변화가 그루브의 절반
    + 하이햇 패턴에 `x`와 `o`를 섞음
    + 스네어 고스트 노트는 `o`

## 보컬 곡의 편곡
- 보컬이 부르는 동안 같은 음역의 리드는 쉼
    + 리드는 보컬 줄 끝의 긴 음이나 쉼표 자리에서 응답
- 벌스는 드럼, 베이스, 가벼운 아르페지오 정도로 비움
- 코러스에서 패드와 스탭을 더하되 보컬 음역(C4-A4 부근)에 지속음을 쌓지 않음
- 화음과 더블은 코러스에만 사용

## lint 항목 해설
| 코드 | 뜻 | 대응 |
|---|---|---|
| `key.outside` | 조와 코드 어디에도 속하지 않는 음 | 의도한 반음계인지 확인, 비율이 15%를 넘으면 경고 |
| `harmony.avoid_note` | 코드음 반음 위의 긴 음 | 음을 바꾸거나 짧게 하거나 약박으로 이동 |
| `harmony.strong_beats` | 강박의 음 중 코드음 비율이 절반 미만 | 강박 음을 코드음으로 조정 |
| `bass.off_chord` | 코드가 바뀌는 자리의 베이스가 코드음이 아님 | 근음 또는 5음으로 변경 |
| `clash.semitone` | 두 트랙이 반음 간격으로 길게 겹침 | 한쪽 음 변경 |
| `range.<역할>` | 역할의 통상 음역을 벗어난 음 | `octave` 조정 |
| `mud.low_voicing` | C3 아래의 좁은 음정 | 보이싱을 올림 |
| `mono.chord` | 단음 악기에 화음 입력 | 악기 교체 또는 단선율로 변경 |
| `melody.leap` | 한 옥타브를 넘는 도약 (보컬은 장6도 초과) | 의도 확인 |
| `density.register` | 같은 음역에 성부 과밀 | 옥타브 분산 또는 성부 삭제 |
| `structure.flat` | 섹션 에너지가 전부 비슷함 | 대비 추가 |
| `structure.odd_length` | 홀수 마디 섹션 | 의도 확인 |
| `structure.short` | 곡 길이가 스케치 수준 | 구성 확장 |
| `structure.no_ending` | 마지막 마디까지 연주가 이어지고 끝 처리가 없음 | `ending: hit` 또는 `ending: fade`, 또는 끝맺음 섹션 작성 |
| `chords.missing` | 코드 정의 없음 | 화성 검사를 받으려면 `chords` 지정 |
| `vocal.overlap` | 가사 줄이 서로 겹침 | 줄 길이 또는 시작 위치 조정 |
| `lyrics.*` | 가사 관련 | `vocals.md` 참조 |
- 오류(ERROR)는 렌더 전에 반드시 해결
- 경고(WARN)는 하나씩 판단
    + 의도한 불협화나 장르 관습이면 유지
    + 판단 근거를 곡 파일의 `notes`에 남기면 다음 작업 때 같은 고민을 반복하지 않음
- 정보(INFO)는 참고 사항

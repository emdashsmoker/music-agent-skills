# 보컬 제작

## 판단 원칙
- 이 문서의 규칙은 출발점
    + 근거가 부족한 규칙이 있을 수 있으므로 결과가 이상하면 규칙보다 관찰을 우선
- 음성 인식 일치율은 탐지기
    + 일치율은 들어볼 줄을 골라내는 용도
    + 최종 합격 여부는 사람의 청취로 결정
- 사용자가 직접 쓰거나 승인한 가사와 선율은 경고만으로 바꾸지 않음
    + 약한 줄을 발견하면 원본과 후보의 보컬 단독 클립을 함께 제시
    + 선택은 사용자에게 맡김
- 이 문서의 수치는 특정 환경에서 측정한 참고값
    + 엔진 버전, 목소리, 템포가 바뀌면 `vocal-check`로 다시 측정

## 엔진 선택
| 엔진 | 방식 | 강점 | 약점 |
|---|---|---|---|
| `kokoro` | 말하는 목소리를 가창으로 변환 | 설치가 가볍고 발음이 또렷함, 결과가 매번 동일 | 음색이 낭독에 가까움, 24 kHz 대역 |
| `piper` | 말하는 목소리를 가창으로 변환 | 목소리와 언어 선택 폭이 넓음 | 목소리마다 품질 편차가 큼, 22 kHz 대역 |
| `diffsinger` | 가창 전용 보이스뱅크 | 가장 자연스러운 가창, 44.1 kHz | 사용자가 보이스뱅크를 제공해야 함, 렌더가 느림 |
- 목소리 목록은 `voices` 명령으로 확인
    + 기본 여성 목소리 : `kokoro` / `af_heart`
    + 기본 남성 목소리 : `kokoro` / `am_michael`
    + Piper 목소리는 데이터셋마다 이용 조건이 다르므로 선택 전에 해당 목소리의 모델 카드를 확인하여 사용자에게 고지
- 다른 언어는 해당 언어의 Kokoro 목소리 또는 Piper 목소리를 지정하면 같은 변환 경로로 가창
    + `vocal-check --asr-model base` 또는 `small`로 다국어 인식 모델 사용
- 기획 단계에서 엔진과 목소리를 사용자에게 질의
    + 사용자가 가창 보이스뱅크를 가지고 있으면 `diffsinger`를 우선 제안

## 트랙 설정
```yaml
vox:
  role: vocal
  vocal:
    engine: kokoro
    voice: af_heart
    style: {vibrato_depth: 20, scoop: 0.4}   # 선택
    ending_fix: true                         # 줄 끝 보강, 기본 켜짐
  layers:
    - {type: double, sections: [chorus1, chorus2]}
    - {type: harmony, steps: 2, sections: [chorus2]}
  mix: {gain_db: 0, reverb: 0.2}
```
| `style` 키 | 기본값 | 내용 |
|---|---|---|
| `vibrato_depth` | 28 | 긴 음의 비브라토 깊이(센트), 0이면 끔 |
| `vibrato_rate`, `vibrato_delay` | 5.6, 0.28 | 비브라토 속도(Hz), 시작 지연(초) |
| `glide` | 0.07 | 음 사이 이동 시간(초) |
| `scoop` | 0.6 | 프레이즈 첫 음을 아래에서 올려 잡는 폭(반음) |
| `preparation` | 0.12 | 음이 바뀌기 직전 반대 방향으로 살짝 움직이는 비율 |
| `drift` | 6 | 느린 음정 흔들림(센트) |
| `fall` | 0.35 | 프레이즈 끝에서 음정이 처지는 폭(반음) |
| `level` | 0.6 | 음절 음량을 고르게 맞추는 강도(0에서 1) |
| `ring` | 3 | 모음의 3 kHz 부근 강조(dB), 자음에는 적용 안 됨 |
| `consonant_ceiling` | -3 | 무성 자음의 최대 크기(dB, 그 줄의 모음 크기 기준), 넘는 t, s, k만 최대 6 dB 줄임 |
| `formant` | 0 | 포먼트 이동(반음), 양수는 가늘고 밝은 음색 |
| `breath` | 0 | 숨소리 비율(0에서 1) |
| `vowel_body` | 0 | 길게 끄는 ee 모음(he, she, we, see)에 그 줄의 다른 모음이 가진 300-1300 Hz 몸통을 최대 10 dB 채우고 쉿 소리를 줄임, 1이 완전한 채움. 24줄 측정에서 ee 몸통 중앙값을 줄보다 8.8 dB 아래에서 6.4 dB 아래로 옮기고 인식 점수는 유지, 모음 색이 ih 쪽으로 조금 움직이므로 청취 필요 |
- 레이어
    + `double` : 같은 선율을 좌우에 한 번씩 더 부름 (다른 테이크, 미세한 음정 차와 시간차)
    + `harmony` : 음계 기준 `steps`만큼 위아래 화음, 코드와 부딪히는 음은 코드음으로 조정
    + `sections`로 적용 구간 제한, 화음은 후렴에만 두는 것이 기본
    + 옵션 : `gain_db`, `pan`, `detune`(센트), `delay_ms`

## 가사 작성 규칙
- 작성 순서
    + 선율의 리듬을 먼저 확정
    + 그 리듬의 강박 위치에 강세 음절이 오도록 가사 작성
    + `lint`로 음절 수와 강세를 확인한 뒤 수정
- 줄 길이
    + 한 줄은 2마디 안팎, 줄 사이에 반 박 이상의 쉼 확보
    + 쉼이 없으면 앞 줄의 끝음과 다음 줄의 첫 자음이 겹침 (`lyrics.no_breath`)
- 음절과 음의 일치
    + 음 하나에 음절 하나
    + 엔진이 세는 음절 수가 기준이므로 `lint`의 단어별 음절 수를 따름
    + 한 음절을 여러 음에 걸칠 때는 `E4:1~D4:1`로 이음
- 긴 음의 끝 음절
    + 2박 이상 끄는 음에는 열린 모음이나 비음으로 끝나는 단어 배치 (day, go, flame, burn)
    + 파열음이나 마찰음으로 끝나는 단어는 긴 음에서 꼬리가 끊김 (`lyrics.long_note_ending`)
- 강세
    + 여러 음절 단어의 강세 음절을 더 강한 박에 배치 (`lyrics.stress`)
    + 강박 순서 : 첫 박, 셋째 박, 둘째와 넷째 박, 8분 뒷박, 16분 자리
- 음 길이
    + 음절 하나는 110 ms 이상 (`lyrics.short_notes`)
    + 빠른 곡에서는 8분음표보다 짧은 음절을 피함
- 음절 수가 흔들리는 단어
    + fire, hour, higher, dial처럼 이중모음 뒤에 약한 모음이 오는 단어는 엔진에 따라 한 음절 또는 두 음절 (`lyrics.unstable_word`)
    + 긴 음 하나에 얹거나 두 음에 나누어 얹고 `lint`로 확인
- 쉼표 위치
    + 단어 중간에 쉼표를 두지 않음 (`lyrics.rest_in_word`)
- 각운
    + `lint`가 줄 끝소리를 나열하므로 (`lyrics.rhymes`) 의도한 짝이 맞는지 확인
- 밝은 자음
    + 줄의 뼈대는 유성 자음(m, n, l, d, b, g, w, r)과 열린 모음으로 세움, t, k, p, s, z, sh는 양념으로 단어당 하나 정도만 쓰고 길게 끄는 음 바로 앞에는 두지 않음
    + 말소리 보이스는 이 소리에서 침이 튀고 쉿 소리를 내며 그 파열은 한 줄에서 가장 큰 피크(모음 몸통보다 최대 13 dB 위)에 쇳소리가 섞인 것이라, 이 소리로 세운 줄은 믹스에서 튀어나오고 리미터를 먼저 일하게 함 (`lyrics.bright_consonants`: 다섯 음절에 밝은 소리 셋 이상이거나 연속 3음절, st나 sk 같은 군은 둘로 셈)
- 길게 끄는 ee 모음과 약한 기능어
    + ee 단어(he, she, we, see, me, be, free)를 길게 끌면 얇게 나옴, 이 모음은 몸통 성분이 적고 늘리기가 그 성질을 그대로 두므로 이웃보다 작게 들리고 남은 소리는 쇳소리로 울려 작으면서 날카롭게 들림 (Kokoro 목소리의 7곡 측정에서 ee 음절의 몸통 대역이 그 줄보다 9 dB 낮음)
    + ee 단어는 짧은 음에 두고 길게 끄는 음에는 열린 모음(ah, oh, oo, ay)을 배치(`lyrics.held_ee`), 또는 `style: {vowel_body: 1}`로 모음을 채움
    + 약한 기능어(to, the, a)도 같은 이유로 긴 음에서 묻힘

## 전달이 약해지는 유형
| 유형 | 실제 관측 예시 | 처방 |
|---|---|---|
| 짧은 음에 자음이 몰림 | 128 bpm 한 박 음의 "fields of snow", 156 bpm 8분음표의 "only snow" | 음을 늘리거나 자음이 적은 단어로 교체 (hills of snow) |
| 빠른 음절의 연속 | 156 bpm에서 8분음표로 이어지는 벌스 전체 | 한 박에 한 음절로 리듬을 다시 작성 |
| 약한 기능어가 연달아 놓임 | come what may | 내용어가 섞인 표현으로 교체 (anyway) |
| 줄 첫머리가 약한 음절 | someone is singing | 강한 자음으로 시작하는 단어를 앞에 배치 (voices are singing) |
| 긴 음 뒤의 파열음 | hold the light | 열린 모음이나 비음으로 끝나는 단어로 교체 |
| 한 줄에 몰린 t, s, z (침 튀는 소리, 피크, 쇳소리) | tests at last | 소리를 흩어 놓거나 유성 자음(m, n, l, d)이 있는 단어로 교체 |
| 길게 끄는 ee 단어 (얇고 쇳소리로 울림) | we will see | 짧은 음으로 옮기거나 열린 모음 단어로 교체 |
| 음절 수가 흔들리는 단어 | fire, hour | 음 배치를 바꾸거나 다른 단어 사용 |
| 목소리 음역 밖의 선율 | 낮은 음에서 숨소리만 남는 줄 | 조 또는 옥타브 이동 |
- 이 표는 위험 요인 목록
    + 해당 유형이라도 목소리와 선율에 따라 멀쩡한 경우가 많음
    + 약한지 여부는 `vocal-check`로 확인
- 같은 가사도 목소리에 따라 결과가 다름
    + 한 목소리에서 약한 줄이 다른 목소리에서는 멀쩡할 수 있으므로 목소리를 바꾸면 다시 확인
- 처방은 조건부
    + 약한 줄로 확인된 경우에만 적용
    + 멀쩡한 줄에 미리 적용하면 가사만 어색해짐
- 빠른 템포의 기준
    + 음절 하나가 200 ms 안팎보다 짧아지면 가창 전용 보이스뱅크에서도 자음이 뭉개지기 시작 (`lyrics.fast_syllables`)
    + 150 bpm 이상에서는 8분음표 음절의 연속을 피하고 한 박에 한 음절로 시작

## 확인 절차
- 1단계 : 믹스 전에 보컬만 렌더
    + `python scripts/studio.py vocal-check song.yaml`
    + 줄마다 인식 결과, 일치율, 음정 오차(센트)를 출력
    + 모음이 잡음으로 불렸거나 거의 들리지 않는 음절은 `ROUGH` 표시와 함께 출력 (말하는 목소리 엔진)
    + 일치율 0.85 미만이거나 `ROUGH` 표시가 있는 줄은 그림과 단독 클립이 `vocals/` 폴더에 저장됨
- 일치율과 `ROUGH`는 서로 다른 결함을 잡음
    + 일치율 : 단어가 다르게 들리는 줄
    + `ROUGH` : 단어는 알아듣지만 거슬리는 음절 (숨소리로 끌린 모음, 삼켜진 음절)
    + 일치율 1.00인 줄에서도 `ROUGH`가 나올 수 있으므로 둘 다 확인
- 2단계 : 약한 줄의 그림 확인
    + 위쪽 그림 : 모음 구간에 가로 줄무늬(배음)가 끝까지 이어지는지 확인, 줄무늬 대신 얼룩이면 속삭임 상태
    + 아래쪽 그림 : 음정 곡선이 음표 막대 위에 놓이는지 확인
    + 음절 표시선이 실제 소리의 시작과 맞는지 확인
- 3단계 : 후보 비교
    + 같은 음절 수의 대안 3-5개를 준비
    + `python scripts/studio.py vocal-try song.yaml --line 13 --text "over hills of snow" --text "over miles of snow"`
    + 후보 하나에 몇 초면 끝나며 일치율과 단독 클립을 함께 출력
- 4단계 : 선택
    + 사용자가 쓴 가사이면 원본과 후보 클립을 제시하고 사용자가 선택
    + 직접 쓴 가사이면 뜻과 각운을 해치지 않는 후보를 채택
- `ROUGH` 음절의 처리
    + 그림에서 해당 음절이 줄무늬 대신 얼룩이면 실제 결함
    + 음을 늘리거나, 음절 앞뒤의 자음이 적은 단어로 바꾸거나, 목소리를 바꿔 다시 확인
    + 짧은 음에서 자음이 대부분을 차지해 생긴 표시는 그대로 두어도 무방
- 자음이 따갑거나 묻힐 때의 처리
    + 특정 단어의 t, s가 따갑다는 청취 의견이면 `style: {consonant_ceiling: -6}`으로 낮춘 뒤 `vocal-check`로 일치율 유지 확인
    + 자음이 묻혀 가사가 안 들리면 `consonant_ceiling: 0`으로 올림
- 인식과 표시로 잡히지 않는 결함
    + 줄 끝의 떨림, 지직거림, 특정 음절의 과한 세기는 일치율과 `ROUGH`에 나타나지 않음
    + 그림에서 줄 끝의 배음 줄무늬가 얼룩으로 번지거나 음량이 들쭉날쭉하면 의심
    + 최종 판정은 청취이므로 사용자에게 줄 끝을 들어보도록 안내
    + 보컬 처리 방식을 바꾼 뒤에는 고친 곳 외에 줄 끝과 긴 음도 다시 확인
- 인식 결과 해석 시 주의
    + 앞 줄의 끝음이 클립에 섞이면 첫 단어가 달라질 수 있음
    + 길게 끄는 음에서 인식기가 같은 글자를 반복하는 경우는 점수 계산에서 한 글자로 처리됨
    + 고유명사와 드문 단어는 가창과 무관하게 인식률이 낮음

## 말하는 목소리를 가창으로 바꾸는 방식
- 변환 순서
    + 엔진이 가사 한 줄을 낭독
    + 낭독을 음높이, 음색, 숨소리 성분으로 분해
    + 모음 시작이 박에 오도록 시간축을 다시 배치, 자음은 박 앞으로 보냄
    + 모음에서 가장 안정적이고 밝은 순간만 늘려 긴 음을 채움, 숨소리나 폐쇄 구간은 늘리지 않음
    + 엔진이 알려준 모음 위치에 목소리가 없으면 같은 음절 안에서 실제 유성 구간을 찾아 경계를 옮김
    + 속삭이듯 낭독된 모음은 유성음으로 다시 합성하고 모음의 숨소리 양에 상한을 둠
    + 늘린 구간 뒤의 음절 끝부분은 줄의 보통 모음 크기를 넘지 않게 제한 (음절 끝이 튀는 현상 방지)
    + 자음으로 끝나는 프레이즈의 마지막 음절은 낭독의 잦아드는 구간을 그대로 쓰되 음량 곡선을 고르게 다듬어 한 방향으로만 줄어들게 함 (낭독 끝의 갈라지는 목소리가 떨림으로 들리는 현상 방지)
    + 음높이를 노래 곡선으로 교체한 뒤 다시 합성
    + 무성 자음은 원본 녹음에서 그대로 가져와 선명도 유지
    + 모음보다 크게 낭독된 t, s, k는 `consonant_ceiling`까지 줄임 (낭독에서는 자연스러운 크기가 노래에서는 따갑게 들림)
- 엔진의 시간 정보 보정
    + 엔진이 알려주는 음소 시각은 실제 소리보다 늦음
    + 곡의 모든 줄에서 치찰음과 유성음의 경계를 관측하여 지연량을 측정, 고정값을 쓰지 않음
    + 지연량은 낭독 속도에 반비례하므로 줄마다 속도로 환산하여 적용
    + 단어 사이 공백 구간은 실제로는 앞뒤 소리가 차지하므로 엔진별 실측 비율로 나눔
- 낭독 속도
    + 음이 길면 느리게, 짧으면 빠르게 낭독시켜 늘리는 양을 줄임
    + `vocal: {speed: 0.9}`로 고정 가능

## 줄 끝 보강
- 배경
    + 말하는 목소리는 문장 끝 단어를 흐리게 끝냄
    + me, sea, you처럼 닫힌 모음으로 끝나는 줄에서 끝음이 속삭임이 되기 쉬움
- 1차 대응은 항상 적용
    + 낭독의 흐려진 꼬리를 잘라내고 모음의 안정 구간만으로 긴 음을 채움
- 2차 대응은 줄마다 자동 판정
    + 끝 모음의 유지 지점이 무성음이거나, 주기성이 0.5 미만이거나, 다른 모음보다 9 dB 이상 작으면 발동
    + 줄 뒤에 짧은 단어(영어는 but)를 붙여 한 번 더 낭독시키면 원래의 끝 단어가 문장 중간이 되어 또렷해짐
    + 마지막 음절의 시작점에서 짧은 크로스페이드로 이어 붙임
    + 직전 음절의 음량에 맞춰 높이를 조정
- 안전 장치
    + 단어를 붙였을 때 원래 줄의 발음이 달라지면 보강을 포기
    + 붙임 단어가 등록되지 않은 언어에서는 발동하지 않음 (등록 언어 : en, de, es, fr, it, pt, nl)
    + 결과는 줄 단위로 캐시
- `vocal-check` 출력의 `ending resung` 표시로 발동 여부 확인
- `ending_fix: false`로 끌 수 있음

## 믹스 연계
- 보컬 대 반주는 두 대역에서 따로 확인
    + 300-3400 Hz (몸통) : 보컬이 반주보다 0-12 dB 높아야 함 (`vocal_body_db`)
    + 1.3-5 kHz (자음) : 보컬이 반주보다 2 dB 이상 높아야 함 (`vocal_consonant_db`)
    + 섹션별 자음 대역 수치도 보고되므로 후렴에서만 묻히는 경우를 발견 가능
- 반주 쪽 조치를 우선
    + 보컬 구간에서 리드와 패드를 줄이거나 음역을 비움
    + `master.vocal_carve`로 반주의 자음 대역을 추가로 덜어냄
- 보컬 리버브와 딜레이는 킥 사이드체인을 받지 않음
    + 잔향이 박마다 끊기면 보컬이 조각나 들림
- 목소리를 바꾸면 믹스 수치를 다시 확인
    + 목소리마다 음색 중심이 달라 같은 설정에서도 묻히는 정도가 달라짐

## DiffSinger 보이스뱅크
- 보이스뱅크는 사용자가 제공한 것만 사용
    + 폴더 경로, 압축 파일 경로, 사용자가 직접 건넨 저장소 주소를 `voice`에 지정
    + 보이스뱅크를 찾아주거나 대신 내려받는 행동은 하지 않음
- 사용 전 확인
    + `python scripts/studio.py diffsinger-inspect <경로>`
    + 화자, 언어, 포함된 모델, 이용 조건이 적힌 파일 목록을 출력
    + 목록의 파일과 배포 페이지의 이용 조건을 읽고 사용자에게 요약 고지 (상업적 이용, 표기 의무, 금지 내용, 생성물 이용 제한)
    + 조건에 어긋나는 가사나 용도이면 진행 전에 사용자와 상의
- 설정
```yaml
vocal:
  engine: diffsinger
  voice: /path/to/voicebank
  lang: en              # 보이스뱅크가 지원하는 언어 코드
  speaker: normal       # 선택, {normal: 0.7, soft: 0.3} 형식으로 혼합 가능
  steps: 20             # 음색 모델 샘플링 횟수, 높을수록 느리고 정교함
  pitch: model          # model은 보이스뱅크의 음정 모델, curve는 내장 음정 곡선
  gender: 0             # 음색 이동 (-1에서 1)
  breathiness: 0        # 숨소리 가감 (dB)
  tension: 0            # 긴장도 가감
```
- 화자와 음색
    + 화자가 여럿이면 또렷한 화자와 부드러운 화자의 전달력이 다름
    + 어두운 목소리는 믹스에서 자음 대역이 부족하기 쉬우므로 `vocal_consonant_db`를 보고 3 kHz 부근 EQ와 음량을 목소리마다 따로 조정
- 음역
    + 보이스뱅크마다 편한 음역이 다름
    + 너무 낮거나 높으면 숨소리가 늘고 음정 오차가 커짐
    + `vocal-check`의 음정 오차가 25센트를 넘는 줄이 몰리면 선율을 옮김 (파트의 `octave` 또는 `transpose`)
- 발음
    + 보이스뱅크 사전에 없는 단어는 일반 발음 사전과 발음 변환기로 보충
    + 음절 묶음은 모음에서 시작하며 다음 음절의 첫 자음은 앞 음의 끝에 놓임
- 재현성
    + 줄마다 같은 시드로 시작하므로 같은 입력은 같은 소리
    + 더블은 시드와 음색을 바꾼 별도 테이크
- 렌더 시간
    + 줄 하나에 약 10초 (2코어 CPU 기준), 결과는 캐시되어 재렌더 시 재사용

## 알려진 한계
- 말하는 목소리 경로는 낭독의 음색을 그대로 물려받음
    + 벨팅, 가성, 거친 발성은 표현 불가
    + 말하는 음높이에서 한 옥타브 이상 벗어나면 음색이 가늘어지거나 탁해짐
- 인식 일치율은 영어에서 가장 믿을 만함
    + 다른 언어는 다국어 인식 모델의 정확도만큼만 신뢰
- 빠른 랩과 16분음표 연속 가창은 음절이 뭉개짐
- 엔진 경로의 강세와 쉼표 검사는 말하는 목소리 엔진에서만 수행
    + DiffSinger 트랙은 음절 수와 발음 가능 여부만 검사

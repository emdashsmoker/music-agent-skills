# 믹싱과 검수

## 믹스 구조
- 신호 흐름
    + 트랙 : 악기 렌더, 인서트 이펙트, 필터, 사이드체인, 목표 음량으로 자동 정렬, 팬
    + 버스 : drums, bass, music, fx, vocals
    + 리턴 : reverb, delay (악기용), vox_reverb, vox_delay (보컬용)
    + 마스터 : 22 Hz 하이패스, 110 Hz 아래 모노화, EQ, 글루 컴프레서, 소프트 클립, 리미터
- 음량은 역할별 목표 음량으로 지정됨
    + 믹서가 각 트랙의 실제 음량을 재서 역할의 목표값으로 옮김
    + 패치가 원래 크거나 작아도 같은 자리에 놓임
- 전경의 자리는 기획에서 고른 믹스 스타일이 정함
    + 곡 파일의 `mix.style`이 역할 기본값과 장르 프로필 위에 오프셋을 얹음 (아래 믹스 스타일 절)
- 조정 손잡이의 우선순위
    + 1순위 : 트랙의 `mix.gain_db` (역할 기본값과 스타일 오프셋에서 몇 dB 가감)
    + 2순위 : 섹션의 `vel` (특정 섹션에서만 세기 조절)
    + 3순위 : 트랙의 `reverb`, `delay`, `duck`, `hpf`, `lpf`
    + 4순위 : 인서트 EQ
    + 마스터 EQ는 버스 균형을 맞춘 뒤 마지막에 사용

## 마스터 설정
| 키 | 기본값 | 내용 |
|---|---|---|
| `lufs` | -10 | 목표 통합 음량 |
| `ceiling` | -1 | 트루 피크 상한(dBTP) |
| `glue` | true | 버스를 묶는 가벼운 컴프레서 |
| `clip` | true | 가장 높은 순간 피크만 깎는 소프트 클립 |
| `eq` | 없음 | 마스터 EQ 밴드 (표기는 `sound.md`의 `eq`와 같음) |
| `vocal_carve` | -2.5 | 보컬이 울리는 동안 music 버스의 1.3-5 kHz를 덜어내는 양(dB). 믹스 스타일이 이 값을 옮김 |
| `mono_below` | 110 | 이 주파수 아래를 모노로 합침 |
| `sidechain_release` | 0.5 | 사이드체인 회복 시간(박) |
| `fade_out` | 0 | 곡 끝 페이드(박) |
- 장르별 목표 음량의 출발점
    + 조용하고 다이내믹한 장르 (앰비언트, 로파이, 두머 등) : -17에서 -12
    + 팝과 하우스 계열 : -11에서 -9
    + 강한 클럽 장르 (하드스타일, 개버, 빅룸) : -8에서 -7
- 리미터가 많이 일할수록 킥이 눌리고 펌핑이 생김
    + `limiter_p95_db`가 5를 넘으면 목표 음량을 낮추거나 가장 큰 버스를 줄임

## 믹스 스타일
- 전경(백비트, 리드, 리드 보컬)을 트랙의 어디에 둘지는 취향이므로 기획에서 묻고 곡 파일의 `mix.style`에 기록
    + 연주곡은 백비트와 리드만 움직이고, 보컬곡은 보컬 음량과 `vocal_carve`와 판정 창이 함께 움직임
    + 밝기, 공간, 장르 프로필의 다른 값은 그대로 유지
    + 보컬 전면과 백비트 전면은 전면의 두 반쪽. 보컬 전면은 연주곡에서 리드만 1 dB 올리므로 연주곡에는 제시하지 않음. 백비트 전면은 snare 역할에만 걸리므로 킥과 햇으로만 가는 곡에는 제시하지 않음
- 스타일별 오프셋

| 스타일 | 들리는 결과 | 역할 `gain_db` 오프셋 | `vocal_carve` 변화 | 보컬 판정 창 |
|---|---|---|---|---|
| `forward` 전면 | 팝, 라디오 믹스. 목소리와 백비트가 트랙 위에 | snare +1.5, lead +1, vocal +1.5 | -1.5 (기본 -4) | 몸통 1 - 13, 자음 3 - 15 |
| `vocal` 보컬 전면 | 목소리와 리드만 앞에, 백비트는 균형 | lead +1, vocal +1.5 | -1.5 | 전면과 같음 |
| `backbeat` 백비트 전면 | 백비트만 앞에, 목소리와 리드는 균형 | snare +1.5 | 0 | 균형과 같음 |
| `balanced` 균형 (기본) | 역할 기본값 그대로 | 없음 | 0 (기본 -2.5) | 몸통 0 - 12, 자음 2 - 14 |
| `blended` 융합 | 클럽 믹스. 목소리와 리드가 트랙 속에 | lead -1, vocal -1.5 | +1.5 (기본 -1) | 몸통 -2 - 10, 자음 0 - 12 |

- 판정 창이 스타일을 따라 움직이는 이유
    + 사용자가 고른 균형이 렌더마다 경고로 돌아오면 검수 결과가 소음이 됨
    + 창의 이동량은 오프셋이 실제로 옮긴 보컬 여유를 따름. 전면은 약 1 dB 위, 융합은 약 2 dB 아래 (아래 측정)
- `studio render --mix-style <이름>`은 그 실행에서만 곡 파일의 스타일을 덮어씀
    + 같은 곡을 스타일별로 비교해 들을 때 사용
- 스타일의 값은 시험 곡을 스타일별로 렌더하여 정함
    + 측정은 이 문서 끝의 "믹스 스타일의 근거가 된 측정"에 있음
- 준수는 기획에서 스타일과 함께 묻고 기본은 유연
    + (유연) 스타일은 출발점. 검수 결과를 고칠 때 전경 파트의 `gain_db`와 `vocal_carve`를 1-2 dB 단위로 옮겨도 되고 판정 창은 스타일의 것을 유지. 검수 결과나 곡의 성격에 다른 스타일이 더 맞으면 사용자에게 묻지 않고 `mix.style`을 바꾸며, 판정 창은 새 스타일의 것을 따름. 옮긴 파트와 양, 바꾼 스타일과 이유는 보고서와 `notes`에 기록
    + (유연-HITL) 유연과 같은 방식으로 조정하되 스타일 자체를 바꾸는 일은 사용자에게 먼저 질의
    + (고정) 전경 파트(snare, lead, vocal)의 `gain_db`와 `vocal_carve`를 스타일 값에 둠. 편곡, 다른 파트, 음색, EQ로만 고치고, 전경을 옮겨야만 사라지는 결과는 고치지 않고 그대로 보고
    + 이름 붙은 스타일은 목표값처럼 읽혀 조정을 멈추게 하기 쉬우므로 준수를 따로 물음. 기본인 유연은 스타일 변경까지 에이전트에게 맡겨 작업이 질의로 멈추지 않게 하고, 바꾼 내용은 보고서로 사용자에게 돌려줌

## 검수 절차
- `render`가 끝나면 세 가지를 차례로 확인
    + 1단계 : 수치와 발견 사항 (`== metrics ==`, `== findings ==`)
    + 2단계 : 섹션 표 (`== sections ==`)
    + 3단계 : 그림 6장을 직접 열어 확인
- 그림 확인은 생략할 수 없는 정식 단계
    + 수치는 정해진 항목만 검사
    + 그림은 규칙에 없는 이상(구멍, 줄무늬, 한쪽으로 쏠림, 예상 밖의 빈 구간)을 드러냄
- 발견 사항이 0건이어도 그림에서 이상이 보이면 원인을 추적
    + 추가 그림 : `plot --spectrogram <오디오> --start 60 --end 90`, `plot --pianoroll <섹션>`, `plot --chain <트랙>`
    + 트랙 단독 확인 : `render --only <트랙> --sections <섹션>`
- 수정 후에는 같은 수치와 그림으로 다시 확인
    + 고친 항목이 다른 항목을 악화시키지 않았는지 비교

## 수치 해설
| 항목 | 정상 범위 | 벗어났을 때의 뜻 |
|---|---|---|
| `lufs` | 목표값 ±0.5 | 마스터가 목표에 도달하지 못함 |
| `true_peak_db` | -0.3 이하 | 변환 후 클리핑 위험 |
| `crest_db` | 6 - 16 | 낮으면 과압축, 높으면 한 음만 튀거나 편곡이 빈약 |
| `limiter_p95_db` | 5 이하 | 리미터 과로 |
| `slope_db_per_octave` | -4.5 - -0.7 | 낮으면 어둡고 저역 과다, 높으면 얇고 날카로움 |
| `low_share_db` | -9 - -1.5 | 120 Hz 아래 에너지의 비중 |
| `high_share_db` | -30 - -11 | 6 kHz 위 에너지의 비중 |
| `correlation` | 0.2 이상 | 좌우 위상 문제 |
| `low_correlation` | 0.8 이상 | 저역이 모노에서 사라질 위험 |
| `mono_loss_db` | -3 이상 | 모노 재생 시 음량 손실 |
| `drums_vs_rest_db` | -5 - 7 | 낮으면 비트가 묻힘, 높으면 비트가 믹스를 삼킴 |
| `kick_vs_bass_db` | -3 이상 | 킥 타점에서 베이스가 킥을 덮음 |
| `vocal_body_db` | 0 - 12 (균형 기준, 전면 +1, 융합 -2) | 낮으면 보컬이 묻힘, 높으면 보컬이 반주와 분리됨 |
| `vocal_consonant_db` | 2 - 14 (균형 기준, 전면 +1, 융합 -2) | 낮으면 가사가 가려짐 |
| `energy_rank_correlation` | 0.5 이상 | 섹션 음량이 기획한 에너지 곡선을 따르지 않음 |
| `ending_drop_db` | 18 이하 | 마지막 마디가 가득 찬 채로 곡이 뚝 끊김 |
| `silences_s` | 빈 목록 | 곡 중간의 예기치 않은 무음 |
- 임계값은 통상 범위에서 잡은 출발점
    + 장르 프로필의 `qa` 항목이 장르에 맞게 조정 (예시 : 앰비언트는 드럼 관련 기준 완화)
    + 의도한 연출이면 발견 사항을 그대로 두고 이유를 보고에 기록

## 그림 보는 법
- `overview.png` : 파형, 단기 음량과 기획 에너지, 버스별 음량
    + 파형의 끝이 서서히 가늘어지는지 확인, 절벽처럼 끊기면 끝 처리가 없는 곡
    + 파형이 벽돌처럼 꽉 차 있으면 과압축
    + 음량 곡선이 주황색 기획 에너지 계단을 따라 오르내리는지 확인
    + 버스 곡선에서 한 버스가 계속 맨 위에 있으면 그 버스가 믹스를 지배
    + 보컬 곡선이 다른 모든 버스보다 6 dB 넘게 높거나 아래로 묻히는지 확인
- `spectrogram.png` : 시간에 따른 주파수 분포
    + 세로 띠가 일정 간격으로 보이면 킥과 하이햇이 살아 있음
    + 특정 대역이 계속 비어 있으면 그 음역을 맡을 성부가 없음
    + 특정 대역에 가로로 진한 띠가 계속되면 공진 또는 한 음의 과다
    + 필터 움직임은 위로 열리는 삼각형 모양으로 보임
    + 브레이크와 드롭의 경계가 세로선으로 분명한지 확인
- `spectrum.png` : 3분의 1 옥타브 평균 스펙트럼과 버스별 곡선, 회색은 통상 범위
    + 마스터 곡선이 회색 영역을 벗어나는 대역 확인
    + 60-120 Hz에서 drums와 bass 곡선이 같은 높이로 겹치면 킥과 베이스가 충돌
    + 보컬 곡에서는 1-4 kHz에서 vocals가 music보다 위에 있어야 가사가 들림
- `arrangement.png` : 트랙별 연주 구간
    + 섹션마다 의도한 트랙이 켜져 있는지 확인
    + 모든 섹션이 같은 모양이면 전개가 없음
    + 전환 효과(fx_*)가 섹션 경계에 놓였는지 확인
- `pianoroll.png` : 음과 코드
    + 주황색 음은 조 밖의 음
    + 성부들이 같은 음역에 겹쳐 있는지 확인
    + 베이스가 코드 근음을 따라가는지 확인
- `stereo.png` : 좌우 상관과 대역별 폭
    + 상관이 0 아래로 내려가는 구간은 모노에서 소리가 사라짐
    + 저역은 가운데에 모여 있어야 함

## 자주 나오는 문제와 처방
| 증상 | 확인할 곳 | 처방 |
|---|---|---|
| 비트가 묻힘 | `drums_vs_rest_db` 낮음, overview의 drums 곡선 | 패드와 코드의 `gain_db` 인하, 사이드체인 강화, 킥 `gain_db` 인상 |
| 비트가 믹스를 삼킴 | `drums_vs_rest_db` 높음, 파형이 킥 모양으로만 보임 | 킥과 스네어 `gain_db` 인하, 음악 버스 성부 보강 |
| 킥과 베이스 충돌 | `kick_vs_bass_db` 낮음, spectrum의 60-120 Hz | 베이스 `duck` 강화, 킥 자리의 베이스 음 삭제, 킥 `tune_hz` 변경 |
| 탁한 중저역 | spectrum의 200-500 Hz 돌출 | 패드와 코드에 `hpf` 250-350, 낮은 보이싱 올리기 |
| 날카로운 고역 | `slope` 높음, `high_share_db` 높음 | 하이햇과 라이드 `gain_db` 인하, 리드 `lpf` |
| 어두운 믹스 | `slope` 낮음 | 리드와 플럭의 필터 열기, 하이햇 추가, 마스터 EQ는 마지막 수단 |
| 보컬이 묻힘 | `vocal_body_db` 낮음 | 보컬 구간에서 같은 음역 성부 제거, 보컬 `gain_db` 인상 |
| 가사가 가려짐 | `vocal_consonant_db` 낮음 | 리드와 하이햇을 보컬 구간에서 줄임, `vocal_carve` 강화, 보컬 3-4 kHz 보강 |
| 자음이 따가움 (t, s, z: 피크, 쇳소리) | 보컬 줄마다 먼저 청취, 수치로는 `limiter_p95_db` 상승 정도만 보임 | `style: {consonant_ceiling: -6}` 후 `vocal-check`로 일치율 확인 |
| ee 단어가 이웃보다 작게 들리거나 쇳소리로 울림 (TTS 목소리) | 보컬 줄마다 청취, `ROUGH`가 놓칠 수 있음 | 가사를 바꾸거나 음을 짧게 조정, 크기를 올리면 쉿 소리도 같이 올라감 |
| 보컬이 반주와 분리됨 | `vocal_body_db` 높음 | 보컬 `gain_db` 인하, 보컬 리버브 증가 |
| 드롭이 약함 | `energy_rank_correlation` 낮음 | 드롭 직전 섹션을 비우고 드롭에 성부 추가 |
| 리미터 과로 | `limiter_p95_db` 높음 | 목표 `lufs` 인하, 가장 큰 버스 인하 |
| 모노에서 사라짐 | `correlation` 낮음 | 넓은 패드의 `width` 인하, 코러스 이펙트 약화 |
| 곡이 뚝 끊김 | `ending_drop_db` 높음, overview 파형의 끝이 절벽 모양 | `ending: hit` 또는 `ending: fade`, 마지막 화음에 음량 감쇠 |
- 한 번에 한 가지만 바꾸고 다시 렌더
    + 여러 개를 동시에 바꾸면 어느 조치가 효과를 냈는지 알 수 없음
- 부분 렌더로 반복 시간을 줄임
    + 문제 섹션만 `--sections`로 렌더하여 수치 변화를 확인한 뒤 전체 렌더

## 긴 곡의 자원 사용
- 6분이 넘는 곡은 버스 버퍼를 출력 폴더의 `build/work/`에 임시 파일로 두고 사용
    + 렌더가 끝나면 자동 삭제
    + 15분 곡 기준 메모리 약 3 GB, 임시 디스크 약 3 GB
- `build/cache/`의 트랙 캐시는 재렌더를 빠르게 하는 용도
    + 디스크가 부족하면 삭제해도 결과는 같음
- 렌더 시간의 기준 (2코어 CPU)
    + 3-4분 곡 : 2-3분
    + 7분 곡 : 4분 안팎
    + 보컬 합성 : TTS 목소리는 줄당 3-5초, 가창 보이스뱅크는 줄당 약 10초

## 재현성
- 같은 곡 파일과 같은 `seed`는 같은 오디오를 생성
    + 드럼의 노이즈, 휴머나이즈, 보컬의 미세 흔들림 모두 시드에서 파생
- TTS 엔진과 가창 모델도 고정 시드로 실행
- 중간 결과는 출력 폴더의 `build/`에 캐시되어 바뀐 트랙만 다시 계산

## 믹스 스타일의 근거가 된 측정
- 보컬 시험곡 4곡(퓨처팝 2곡, 콜드웨이브 1곡, 두머 1곡, 모두 Kokoro 목소리)과 연주곡 6곡(예제 First Light와 Silver Box, 보컬곡 4곡의 보컬 트랙을 뺀 판)을 스타일마다 렌더
    + 음량, 리미터 작동량, 크레스트는 세 스타일에서 0.1 LU 안에서 같음. 스타일은 레벨 창과 카브만 옮기므로 마스터는 변하지 않음
    + 연주곡에서는 스네어와 리드의 목표 음량이 오프셋만큼 정확히 움직이고(전면 +1.5와 +1, 융합 리드 -1), `drums_vs_rest_db`는 0.5 dB 안에서 같음
- 보컬곡의 `vocal_body_db`와 `vocal_consonant_db` (곡 전체, 괄호는 자음 여유가 가장 낮은 섹션)

| 곡 | 균형 몸통 / 자음 | 전면 몸통 / 자음 | 보컬 전면 몸통 / 자음 | 융합 몸통 / 자음 |
|---|---|---|---|---|
| 퓨처팝 A | 2.9 / 4.2 (3.2) | 4.1 / 5.1 (3.9) | 4.2 / 5.8 (4.7) | 1.5 / 2.7 (1.5) |
| 콜드웨이브 | 3.9 / 3.9 (2.6) | 5.0 / 5.1 (4.0) | 5.3 / 5.4 (4.3) | 2.5 / 2.3 (0.9) |
| 퓨처팝 B | 2.3 / 5.0 (3.9) | 3.5 / 5.7 (4.5) | 3.7 / 6.5 (5.4) | 1.0 / 3.4 (2.1) |
| 두머 | 3.4 / 3.8 (2.5) | 4.3 / 4.7 (3.4) | 4.7 / 5.3 (4.0) | 2.0 / 2.3 (0.9) |

- 전면은 몸통을 1.0에서 1.2 dB, 자음을 0.7에서 1.3 dB 올리고, 융합은 몸통을 1.3에서 2.5 dB, 자음을 1.5에서 2.2 dB 내림
- 보컬 전면은 몸통을 1.3에서 1.4 dB, 자음을 1.5에서 1.6 dB 올림. 스네어가 제자리라 전면보다 자음 여유가 0.4에서 0.9 dB 더 남음. 콜드웨이브는 드럼이 원래 낮은 믹스라 이 스타일에서 `drums_vs_rest_db`가 -5를 넘어 비트가 묻힌다는 결과가 켜지며, 유연 준수에서 드럼을 1 dB 올리는 조정이 그 예
- 백비트 전면은 따로 렌더하지 않음. 보컬 여유에 주는 효과는 전면과 보컬 전면의 차이(자음 -0.4에서 -0.9 dB)이고, 연주곡에서는 스네어 오프셋만큼 움직임
    + 전면 창을 2 dB 올렸을 때는 4곡 중 3곡에서 가장 낮은 섹션의 자음이 경고에 걸렸으므로 창의 이동은 1 dB로 정함
    + 융합 창을 2 dB 내리면 4곡 모두 경고 없이 창 안에 들어옴

# 기획

## 기획의 목적
- 렌더 전에 곡의 큰 결정을 사용자와 합의
    + 전체 곡 렌더와 보컬 합성은 시간이 드는 작업이므로 방향이 틀리면 손실이 큼
- 합의한 내용은 곡 파일의 `notes`에 요약
    + 이후 수정 요청 때 판단 기준으로 사용

## 질의 항목
| 항목 | 기본값 | 비고 |
|---|---|---|
| 장르 | 사용자 요청에서 추정 | `genres` 목록에서 가장 가까운 id 제시 |
| 분위기와 레퍼런스 | 장르 표준 | 레퍼런스는 템포, 리듬, 음색, 구성의 특징만 참고 |
| 템포 | 장르 기본 bpm | `genres <id>`의 범위 안에서 제안 |
| 조 | 장르의 첫 번째 조 | 보컬이 있으면 목소리 음역에 맞춰 조정 |
| 길이 | 장르 표준 (팝 3-4분, 클럽 5-8분) | 마디 수로 환산하여 제시 |
| 구성 | 장르 표준 구성 | 섹션 목록과 마디 수를 표로 제시 |
| 보컬 | 없음 | 있으면 아래 보컬 항목 질의 |
| 전달 형식 | mp3와 MIDI | ogg, wav, flac, 스템, LMMS, DAWproject는 요청 시 |
| 음량 목표 | 장르 프로필 | 스트리밍용, 클럽용 등 용도가 있으면 반영 |
- 보컬이 있는 경우의 추가 질의
    + 엔진과 목소리 (`voices` 목록 제시, 가창 보이스뱅크 보유 여부 확인)
    + 언어
    + 가사 : 사용자가 제공 또는 주제를 받아 작성
    + 성별과 음역 선호
- 질의는 한 번에 묶어서 진행
    + 항목마다 기본값을 함께 제시하여 사용자가 바꿀 것만 답하면 되도록 구성
- 사용자가 일임하면 기본값으로 진행
    + 어떤 가정을 했는지 첫 보고에 명시
- 질의가 불가능한 실행 환경이면 기본값으로 진행하고 가정을 보고서 맨 위에 기록

## 기획 요약 양식
```
제목 / 장르 / 템포 / 조 / 길이
구성 : intro 8 - verse 16 - chorus 16 - ... (총 N마디, M분 S초)
코드 : verse i VI III VII / chorus VI VII i i
핵심 아이디어 : (훅, 음색, 전개의 특징 한두 줄)
보컬 : 엔진, 목소리, 음역, 가사 주제
전달물 : mp3, MIDI, ...
```
- 이 요약을 사용자에게 보여주고 확인을 받은 뒤 작곡 시작
- 가사를 새로 쓰는 곡은 가사 초안도 함께 확인

## 사용자 입력의 처리
- 사용자가 준 선율, 코드, 리듬 아이디어는 그대로 반영
    + 문법에 맞게 옮긴 뒤 `lint` 결과를 공유
    + 화성 충돌이 있으면 위치와 대안을 제시하고 선택을 요청
- 사용자가 준 가사는 원문 유지가 원칙
    + 음절 수, 강세, 줄 끝 모음, 각운을 점검
    + 문제가 있는 줄의 목록과 수정안을 제시
    + 승인된 수정만 반영
- 레퍼런스 곡은 특징만 참고
    + 특정 곡의 선율이나 가사를 옮겨 쓰지 않음
- MIDI 파일을 받으면 `import-midi`로 곡 파일 초안을 만든 뒤 악기와 역할을 지정

## 무리한 기획의 처리
- 품질을 크게 해칠 요청의 예
    + 장르 관습과 크게 어긋나는 템포 (예시 : 90 bpm 개버)
    + 목소리 음역을 크게 벗어난 선율
    + 한 음에 여러 음절을 넣거나 110 ms보다 짧은 음절이 이어지는 가사
    + 각운과 음절 수가 줄마다 제각각인 가사
    + 전개 없이 같은 섹션만 반복되는 긴 구성
- 대응 순서
    + 1단계 : 무엇이 문제이고 결과가 어떻게 나빠지는지 구체적으로 설명
    + 2단계 : 의도를 살리는 대안을 1-2개 제시 (예시 : 각운만 맞춘 수정 가사)
    + 3단계 : 사용자의 선택을 받음
- 임의로 고쳐서 진행하지 않음
    + 고친 결과가 사용자의 의도와 다를 수 있음
- 사용자가 원안을 고수하면 원안대로 진행
    + 예상되는 품질 저하를 한 번 명확히 고지
    + 결과 보고에 해당 부분의 수치와 한계를 기록
- 사용 조건이 붙은 목소리나 보이스뱅크를 쓰는 경우
    + 조건에 어긋나는 가사나 용도이면 진행 전에 사용자에게 알리고 조정

## 진행 중 보고
- 단계가 끝날 때마다 짧게 공유
    + 구성과 코드 확정 시
    + 보컬 확인 결과 (약한 줄과 후보)
    + 첫 전체 렌더의 수치와 그림에서 본 것
- 사용자의 판단이 필요한 지점
    + 가사 변경
    + 약한 줄의 후보 선택
    + 의도한 연출과 QA 기준이 충돌할 때
